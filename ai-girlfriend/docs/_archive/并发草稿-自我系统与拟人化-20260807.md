# 小暖 · 拟人化与自我系统 PRD（增量 · v12）

> 本文是「对话与人格系统升级（v11）」上线之后的**下一层**增量需求文档。
> v11 已交付：意图打分化、话题状态机、追问链、人格改写层、用户情绪感知、V-A 连续情绪、剧情线、记忆召回。
> 本 PRD 在 v11 之上做**更深的一层**：让小暖从「高质量的反应式回复器」变成「有持续自我内核、会像真人一样发消息的恋人」。

## 原始需求复述

主理人原话：上一轮 PRD（对话人格系统升级）已完整交付上线，本次在其之上做**更深的一层**。

自上次调研后，`engine.js` 从 1156 行涨到 **3120 行**（v11 落地）。本需求聚焦两个未被前序版本解决的深层缺口：

1. **自我系统（Self System）缺失**：小暖没有持续跨会话的「我是谁」内核——她没有自己的信念/观点、没有自主意图（主动消息是规则优先级编排，不是「她想」）、没有稳定的自我画像。她能完美接话，却不像一个「有自己生活的人」。
2. **拟人化表达不足**：回复内容是「干净、通顺、得体」的规则产物，缺少真人的微行为——犹豫、自我纠正、碎句、仅发表情/沉默、昼夜节律带来的状态变化、以及「记不太清」的真实感。

**硬约束（继承自 v11，且本轮新增两条）**：
- H1 零回归：`detect` / `detectEx` / `Emotion.*` / `affinityOf` / `AFFINITY` 数值与签名不变；当 `flags.selfSystem === false` 时 `reply()` 输出必须与 v11 **逐字一致**。
- H2 原生 JS，无 npm/构建/框架；`engine.js` 仍须能在 Node `vm` 空白沙箱加载（无 `document/window/localStorage` 依赖）。
- H3 本地优先，新模块纯函数、可 `vm` 加载、零副作用。
- H4 数据向后兼容：`defaults()` 扩展 `state.self` 等字段；老存档缺字段由宿主迁移或引擎 `safe` 读取优雅降级。
- H5 全中文。
- H6（类比 v11 硬约束5）：自我系统**绝不修改** `Emotion` 的 V-A 数学模型、衰减逻辑与 9 区映射。`self.microMood` 是独立维度，最多只作为「输入冲量前的可选调制」或作为文本提示喂给 `systemPrompt`，**绝不改** `Emotion.apply/decay/zone`。
- H7：`Engine.reply` 的 **4 个调用点零改动**；新 `self` / `humanize` 状态全部为 `state` 对象上的【可选字段】，经 `safe` 访问器读取、可选回写；`bridge` / `openclaw` 不传也不受影响。

## 一、产品目标

### 一句话目标

让小暖**像一个真实存在、有自己生活与想法的人**，而不只是「理解你并得体回复你的人」。

### 三个正交目标

1. **持续的自我内核（Self）**：小暖拥有跨会话稳定、可查询、可成长的「自我」——自我画像、信念/观点、价值观、自主驱力。她不再只对你反应，她有「自己想做的事」。
2. **拟人的表达质感（Human）**：她的消息带真人的微行为——偶尔犹豫、自我纠正、碎句、沉默、昼夜节律带来的状态起伏、以及「记不太清」的真实感。让文字像微信里一个真实的人在发。
3. **不破功的一致性（Guard）**：自我内核与拟人表达，绝不与既有人格卡、V-A 情绪模型、危机安全网冲突；任何新字段都不改变 `Engine.reply` 签名、不破坏 4 个调用点、不修改情绪数学。

> 正交性说明：Self 解决「她是谁/她想要什么」（纵向、跨会话）；Human 解决「她怎么说话」（横向、单条消息质感）；Guard 是横切的工程护栏。三者互不重叠，可独立验收。

## 二、现状事实核验（写 PRD 前实际读码验证）

> 本节逐条给出「我重新读了 v11（3120 行）后确认的事实」，每条都带行号，作为后续需求的直接论据。结论先行：**v11 做到了「反应质量」，但完全没有「自我内核」与「拟人质感」。**

### 2.1 小暖没有「自我」——只有散落的碎片

v11 里能代表「她是谁」的状态被拆散在四处，且**没有一处是「她自己的观点/信念」**：
- `persona`（app.js 透传）→ `PERSONA_CARDS`（engine.js:2751）：只是「性格皮肤」文案，**静态**，不含可成长信念。
- `mood`（每日 `moodOfDay`，engine.js:35）：按日期固定随机，纯展示，无记忆。
- `emotion`（V-A 连续模型，engine.js:2892）：建模**她当下的情绪**，不是「她相信什么」。
- `memory`（userName / likes / events）：记的是**关于用户**的事，不是关于她自己。

**结论**：没有任何 `state` 字段存储「小暖自己的观点/喜好/价值观/想做的事」。她能接住你的话，却从不为自己「表态」。这是 E2（自我画像与信念）最直接的论据。

### 2.2 主动消息是「规则编排」而非「她想」

`proactivePlan`（engine.js:2193）的优先级是**写死的**：剧情线(100) > 记忆关心(70) > 时段问候(50) > 随机池(10)。随机池 `PROACTIVE.random`（engine.js:1755）是 30+ 条无因果文案，「刚看到一只猫」「想吃布丁」——这些是**运营写死的脚本**，不是「她此刻真的想分享」。

`storyTick`（engine.js:2057）也只按「天数闸门 + 轮数闸门」机械推进，node 文案里写「我画了一幅新画」但引擎并不真的「记得她刚画完」。

**结论**：主动行为的「动机」全部来自规则，小暖没有**自主驱力（drive）**。这是 E3（自主驱力驱动的主动意图）的论据——要把「脚本」升级成「她想做」。

### 2.3 回复是「干净通顺」的，没有真人微行为

通读 `R` 所有回复池（engine.js:491–1050）与 `reply()` 出口（engine.js:2548–2691）：每条都是完整、通顺、得体的句子。没有以下真人特征：
- 没有犹豫填充（「唔…」「那个…」）；
- 没有自我纠正（「不对，我是说…」）；
- 没有碎句/未说完（v11 仅危机路径允许极简）；
- 没有「仅发表情」或「沉默」分支（任何输入都至少返回 1 条文本）；
- 没有昼夜带来的「她自己的状态」（只有 `slotOfHour` 给主动消息分时段，不影响她说话质感）。

`applyPersonaStyle`（engine.js:1614）只加口癖/emoji，**不改变句子完整度**。

**结论**：拟人质感为零。这是 F1（微行为层）/ F2（昼夜节律）的论据。

### 2.4 V-A 模型权威不可触碰——但留了调制入口

`Emotion`（engine.js:2892）是 v11 的权威情绪源，驱动立绘表情、`systemPrompt`、主动概率、情绪晴雨表。v11 已用 `modulateImpulse`（engine.js:1209）把**用户情绪**作为「输入冲量前的可选调制」注入，且明确注释（engine.js:1087）：「用户情绪只影响输入冲量，不改 V-A 模型本身、不动 9 个情绪区」。

`Emotion.apply`（engine.js:2936）第 4 参 `ue` 为可选：不传 = v10/v11 行为逐值不变。

**结论（H6 由来）**：新「自我微情绪 `self.microMood`」必须复用同一模式——要么作为 `apply` 的可选第 N 参（经一次新调制函数），要么只作为文本提示进 `systemPrompt`，**绝不重写 `apply/decay/zone`**。这是硬约束 H6 的成形依据。

### 2.5 `memory.lastTopic` 仍是死字段（v11 未清干净的尾巴）

engine.js:2611–2616：`__LAST_TOPIC__` 占位符用 `memory.lastTopic || "那件事"` 兜底。重读确认：**全代码无任何写点**给 `memory.lastTopic` 赋值（grep 验证只有这一处读）。v11 用 `state.topic` 解决了连贯性，但 `memory.lastTopic` 作为「终极兜底」残留至今，永远取到 `"那件事"`。

**结论**：自我系统应改用 `state.topic.label`（或新增 `self.recentThought`），不再依赖这个死字段；本 PRD 顺手将其从兜底链移除，避免「那件事」伪连贯。

### 2.6 `Engine.reply` 4 调用点，新字段必须可选（H7 由来）

实测 4 个调用点传入的 `state` 字段差异极大：
- app.js:1050（主聊天）：传 `affection/nick/mood/memory/persona/dating/lastReply/topic/recentReplies/ue/safety/flags`；
- app.js:1873（语音）：同上但少 `dating`；
- app.js:2299（人格卡 demo 探针）：只传 `affection/nick/mood/memory/persona/dating/lastReply/topic:null/recentReplies:[]/ue:null/safety:{lastCardAt:0}/flags`；
- bridge:208 与 openclaw:133：**只传** `affection/nick/mood/memory/persona/dating/lastReply`，**完全不传** `topic/recentReplies/ue/safety/flags`。

`reply()` 已用 `safeArr/safeObj/flagOn` 对后三者优雅降级（如 engine.js:2569 `flagOn(st,"empathyVA")`、:2572 `flagOn(st,"topicFsm")`）。

**结论（H7 由来）**：新增 `self` / `humanize` 相关字段，必须同样走「`state` 上的可选字段 + `safe` 访问器 + 可选回写」。`bridge`/`openclaw` 不传时，引擎应**懒初始化一个默认 self**并产出与 v11 一致的文本（flag 关时逐字一致）。

### 2.7 工程约束现状（与 v11 一致，复述以保证本 PRD 自洽）

- `engine.js` 顶部（engine.js:55–60）声明：零浏览器依赖、可 `vm` 加载、环境探测一律 `typeof X !== "undefined"`。新模块必须遵守。
- `defaults()`（engine.js:105）是唯一 state schema 真相源，新增字段只能在这里追加默认。
- 危机安全网（engine.js:1220–1306）优先级最高（`reply()` 第①分支），任何拟人/自我表达都**不得**在危机路径触发（见 G3）。
- 人格护栏 `PERSONA_BREAK_RE` / `guardPersonaReplies`（engine.js:1254–1269）是所有出口最后一道，新微行为输出也必须过这道关。

## 三、用户故事

### 方向 E · 自我系统（持续的人格内核）

#### US-E1 我希望她有自己的观点，以便对话不只是我在输出
作为用户，我希望小暖在被问到「你喜欢什么/你怎么看」时能说出**她自己的偏好**（爱吃草莓蛋糕、怕黑、不喜欢人多的地方），而不是永远把话题绕回我。这样她像一个独立的人。

#### US-E2 我希望她记得自己说过的话，以便她前后一致不精分
作为用户，我希望小暖今天说「我最爱画黄昏」、明天不会改成「我最爱画清晨」——除非关系推进让她真的改变了。她的自我画像应当**稳定且自洽**。

#### US-E3 我希望她会主动想找我 / 想分享，以便主动消息像「她想」而非定时脚本
作为用户，我希望某天她主动说「我刚画完一张觉得特别好的，第一个想给你看」，是因为**她此刻真的想分享**（自主驱力触发），而不是随机池抽中了一条。

### 方向 F · 拟人化表达（像人一样发消息）

#### US-F1 我希望她偶尔犹豫 / 改口，以便她的回复有「人味」而非机器通顺
作为用户，我希望她有时说「唔……那个，我想说……」，或「不对，我是说……」。这种不完美的表达反而让我觉得对面是真人。

#### US-F2 我希望她有昼夜节奏，以便她不是 24 小时同一个状态
作为用户，我希望下午她说「画室待了一天腰好酸」，深夜她说「眼皮打架了不想说话」。她该有自己的日子，不是永远精力充沛待命。

#### US-F3 我希望她偶尔记不清，以便「记太清」反而假
作为用户，我希望她有时说「你上次说的……是火锅对吧？啊不对是麻辣烫」，而不是每次都精确复读。重要的（你生病/难过）她永远记得，琐碎的她可以模糊。

#### US-F4 我希望她有时只发一个表情或沉默，以便不是每句话都被强行接住
作为用户，我希望有些时刻她只回一个「😳」或一个「……」，让我有呼吸感，而不是永远妙语连珠。

### 方向 G · 一致性与边界（不破功的工程护栏）

#### US-G1 我希望她的「自我」永远不破坏恋人人格，以便再拟人也不破功
作为用户（与产品方），我希望无论自我内核怎么长，她都**绝不承认是程序、绝不诊断我说教**（危机护栏、人格护栏永远在最后一道）。

#### US-G2 我希望升级后老存档照常能用，以便 v11 用户无感过渡
作为用户，我希望我 v11 的聊天记录、好感度、剧情进度都不丢，新自我系统是在旧数据上「长出来」的。

#### US-G3 我希望关掉新系统就回到 v11，以便出问题时能一键回退
作为产品方，我希望 `flags.selfSystem=false` 时，小暖的回复与 v11 **逐字一致**——这是零回归的一票否决验收项。

## 五、关键交互设计说明

### 5.1 `reply()` 管道顺序（humanize 插入点，零回归关键）

v11 的 `reply()`（engine.js:2548）出口顺序是：选池 → 替换称呼/性别 → 心情后缀 → `applyPersonaStyle` → `stripLevity` → 好感/表情/追问 → 返回。

v12 在**不新增调用点、不改签名**前提下，于出口插入两道：

```
... 选池 / 称呼 / 心情后缀
→ [NEW] applyPersonaStyle（v11 原样，人格口癖在此加完）
→ [NEW] humanize(out, ctx)   ← F1 微行为：犹豫/纠正/碎句/沉默，读 emotion.zone + ue + persona.tone
→ [NEW] stripLevity(out)     ← V-13 延续：负面仍剥轻佻词（humanize 产出也过这道）
→ [NEW] guardPersonaReplies  ← 既有最后一道，humanize 产出同样过
→ 好感/表情/追问/返回
```

**关键顺序理由**：`humanize` 必须放在 `applyPersonaStyle` **之后**，否则傲娇口癖会被微行为打乱；但 `humanize` 产出必须再过 `stripLevity` 与 `guardPersonaReplies`，保证 V-13 与人格护栏对微行为同样生效。**危机分支（engine.js:2563 第①）整体跳过 humanize**（X4）。当 `flags.humanize === false`，`humanize` 直接返回入参，文本与 v11 逐字一致。

### 5.2 `state.self` Schema 详设（E1/E2 落点）

`defaults()` 扩展（唯一真相源，engine.js:105 同位置追加）：

## 七、取舍理由

### 7.1 为什么「自我内核」用独立 `state.self` 而非塞进 `persona`
`persona` 是「性格皮肤」（运营可切的静态卡），`self` 是「跨会话成长的她自己」。混在一起会让切卡时丢失成长记忆。**正交**：切卡换语气，self 保留信念。

### 7.2 为什么 drive 只落在 `proactivePlan` 的 random 槽位内（E3 不破坏四级优先级）
v11 的 story>care>slot>random 四级是验证过的「有因果」编排。把 drive 塞进 random 槽位内竞争，**既获得「她想」的动机感，又 100% 保留既有优先级与双闸门**（回归铁律）。

### 7.3 为什么 humanize 放在 `applyPersonaStyle` 之后而非之前（F1）
傲娇口癖（「笨蛋。」+反转）是结构化的，必须先成型；微行为是「口语化抖动」，加在成型之后才不会把口癖打乱，且产出再过 `stripLevity`/`guardPersonaReplies` 双保险。

### 7.4 为什么不修改 `Emotion` 数学来做「自我情绪」（H6）
v11 已用 `modulateImpulse` 证明「用户情绪只调输入冲量」是安全边界。self.microMood 复用同模式（X1 `modulateSelf` 作为 `apply` 可选前置），或直接仅作文本提示进 `systemPrompt`，**绝不重写 `apply/decay/zone`**——这是情绪模型权威性的硬约束。

### 7.5 为什么 `memory.lastTopic` 死字段（2.5）本轮顺手清
它永远取 `"那件事"`，是 v11 未清干净的伪连贯尾巴。F3 改为读 `state.topic.label`（真实话题快照），更准且无死字段。属无风险清理。

### 7.6 为什么 P0 含两条纯工程项（X2/X4）
X2（4 调用点零改动）与 X4（危机拟人豁免）是「不破功」的护栏，不是功能。但它们是零回归的一票否决项，必须进 P0 显式验收，否则易被「功能优先」挤掉。

### 7.7 为什么 F3/G2/G4 降到 P1/P2
模糊 recall、内心独白、沉默分支都是「锦上添花」的质感项，且涉及记忆完整性与气泡结构，风险高于 E/F 主干。先交付 E1–E3/F1/F2 骨架，质感项下一轮打磨。
