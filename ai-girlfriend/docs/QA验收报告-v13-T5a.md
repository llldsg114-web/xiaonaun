## 三、遗留清单

### 1. A6-a【遗留，**非 T5a 回归**】程序员/程序猿 生产路径仍被误杀 —— 建议 P1

`recallV2` 正确产出 `累坏了吧，程序员不是铁打的。`，但 **engine.js:1322 `guardPersonaReplies`** 用
`PERSONA_BREAK_RE` 判整句，「程序」裸子串命中 → 整句替换为 `PERSONA_FALLBACK`
「我在。你不用一个人扛着，我哪也不去。」

- 实测：程序员 **FALLBACK 179/300**、程序猿 **193/300**，真实回显 **0**
- **用户可见后果**：该族用户在「今天上班好累啊」这类日常句上，收到一句**危机级安慰**，比沉默更突兀
- **A/B 对照 git HEAD**：T5a 前 61.10% → 后 61.95%，**同档，非本轮引入**
- **自检为何漏**：A2-e/A2-f 的「端到端」实为 `M.recallV2()` 模块层直调，**绕过了 guardPersonaReplies**
- memory.js 的 SF 折叠只保护了 *texture 闸*，未能覆盖 *engine 出口闸*（engine 冻结，改不到）
- **修复需决策**：解冻 engine 收窄「程序」为「自称结构 ∧ 程序」，或 memory 侧不回显该族原文（memory 仅余 **2B**，放不下）

### 2. A6-b【**T5a 新引入**】recall 微行为绕过 R30 日配额 —— 建议 P1

`skin()` 产出 `{tx:{kind}}` 经 `Object.assign` 带出，但 **engine.js:2896 recall 早退分支只取 `rv.line`/`rv.factId`，丢弃 `rv.tx`**，返回对象无 `tx` 字段
→ app.js:1087 `textureAfterTurn(est, r.tx || {})` 在 recall 轮恒收 `{}` → `tex.n` 不自增。

- 实测（同日 500 轮）：recall 织入 12 次 + 非 recall 6 次 = 用户当日实感 **18 次**，而 **R30 CAP=6/日 —— 超 3 倍**；纯 recall 场景 `tex.n` 恒 0，即**无上限**
- 连带：若 recall 路径选中 `typo`，`tex.ty` 亦不计，「错字 ≤2/日」同样失效
- **修复方向**：engine 冻结无法在 :2896 补传；建议宿主 app.js 侧由 `Engine.mod("memory")` 返回值补记，或 texture 侧开放显式补计接口
