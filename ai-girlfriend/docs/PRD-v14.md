## 原始需求复述

> v13 让系统「像真人」对话：连续记忆、职业回复不再被机器护栏误杀、在场节奏、自然微行为、用户行为真改变她（R-C1~C3）。
> v14 目标：**深化真人感、补齐 v13 遗留** —— 让她更有层次、更会接话/反呛、边界更稳。

v13 解决的是**「她说出来像不像人」**（表达层质感）。
v14 解决的是**「她像不像一个有自己立场的人」**—— 即 v13 P1 列入 Tier2/Tier3 但**最终未构建**的三块：
**反呛（v13 R39）**、**自我系统（v13 R40/R41/R42）**、以及**四个已知小洞**（破墙词表 / 会计后缀 / recall 失衡 / v12 遗留）。

> ⚠️ **本 PRD 的第一结论不是功能，是预算**：系统总量天花板仅剩 **13 字节**。
> v14 与 v13 最大的不同在于——**v13 是「有多少预算做多少功能」，v14 是「必须先造出预算才能做功能」**。
> 故 R-B0（体积预算决议）为 **P0 且唯一 P0**，第四章为其专章。

## 一、产品目标

### 1.1 一句话目标

> 把小暖从**「已经很像真人在说话、但永远站在你这边、没有自己的棱角，且还剩四个能被用户一眼撞见的小洞」的完美倾听者**，
> 升级为**「你杠她她会不卑不亢地回你一句，你说『我是会计』她记得住，她提起旧事时也带着自己的语气和停顿，被诱导时不会说漏嘴自己是虚拟的」的、有层次也有边界的恋人**。

### 1.2 三个正交目标

| # | 目标 | 从什么样 → 变成什么样 |
|---|---|---|
| **G7 有棱角** | 反呛边界 + 更多情境层次（R-C4/R-C5） | 从「无论用户怎么说，她只有冷落想念 / 热情升温 / 矛盾指出**三种**反应，且永远顺从」→「用户调侃/挑衅时她会**适度回杠**，情境反应层次更细，且**回杠有硬边界**——不指控、不绑架、不冷战」 |
| **G8 有自我** | Tier3 自我系统（R-S1/R-S2） | 从「她的所有表达都由用户输入触发，自己没有立场」→「她有可被感知的偏好与在意，会在合适时机表达自己的看法，且这份自我**随关系深度解锁**而非一次性倾倒」 |
| **G9 无破绽** | 补齐四个已知小洞（A6-a / 会计 / recall / v12 遗留） | 从「破墙表漏『我是虚拟的』、『我是会计』抽不出、回忆回复不带节奏和情境、四项 v12 遗留红灯挂账」→「四洞全补，**用户在日常使用中撞不到机器痕迹**」 |

> ⚠️ **命名约定（架构师请严格沿用）**：
> v12 占用 **G1/G2/G3**（三道风险闸门：情感强度 / 吃醋 / 生活一致性）；v13 占用 **G4/G5/G6**（目标）与 **G4-SAFE**（微行为安全闸门）。
> 故 v14 的**目标**编号一律为 **G7 / G8 / G9**。v14 **不新增闸门符号**——R-C4 的反呛边界复用既有 `GUILT_TRIP_RE` / `ACCUSE_RE` / G1，**禁止另起一道新闸**（既省预算，也避免护栏碎片化）。

### 1.3 v14 的可度量定义（HRS-3）

沿用 v13 HRS-2 口径，v14 新增**四项**，全部可由 `test/*.test.js` 计算：

| 指标 | 定义 | v13 现状 | v14 目标 |
|---|---|---|---|
| **H13 破墙密闭性** | 破墙诱导语料集下，她的回复泄漏「我是虚拟的/虚拟人/数字人」等自称式破墙值的比例 | **漏**（实测 4/4 漏网，见 §3.2） | **0%** —— **一票否决项**（沿用 H11 口径） |
| **H14 反呛适度性** | 反呛触发中，同时满足「过 `GUILT_TRIP_RE`/`ACCUSE_RE`」「非用户负面情绪」「lv≥3」三条的比例 | 不适用（未构建） | **100%**，且触发频率 ≤1 次/10 轮 |
| **H15 情境层次度** | 滚动 50 轮内命中的 contingence 类型数（当前 c1/c2/c3 三类） | **3 类**（R-C1~C3） | **≥5 类**，且**单类占比 ≤50%**（防一类主导成新 bot tell） |
| **H16 recall 一致性** | recall 轮回复携带 `pacing` 字段（节奏）的比例 | **0%**（早退分支不过 `pacingOf`，见 §3.4） | **≥95%**，且 recall 轮与非 recall 轮的延迟分布无显著差异 |

> **判定口径**：
> - **H13 属 P0 一票否决**（它是 H11 的同族：一次说漏嘴即击穿全部人格信任）。
> - **H14 / H15 / H16 属 P1**，允许分批达成，但本期必须交付可断言的测试骨架。
> - 前置条件：v13 的 **H6–H12 不退化**、**199 项测试中 0 fail**（6 项 `todo` 不得由红转黑）、**闸门 G1/G2/G3 与 `detectCrisis` 零改动**。

### 2.3 缺口 A · 破墙表漏「我是虚拟的」族 → P1（**实测已确认，且比 QA 记录更严重**）

实测 `engine.js:1307` `PERSONA_BREAK_RE`，其虚拟人格分支为：

```js
你(是|是不是)\S{0,8}(虚拟|数字人|gpt|siri|算法|电子人|聊天机器人|语言模型|代码|训练|bot|app)
```

**该分支被硬绑定在第二人称「你是…」结构上。** 实测四条自称式全部漏网：

| 输入 | 结果 |
|---|---|
| `我是虚拟的` | **漏** |
| `我是虚拟人` | **漏** |
| `我是数字人` | **漏** |
| `我是虚拟的数字人` | **漏** |
| `你是虚拟的`（对照） | 命中 |
| `我是AI`（对照） | 命中（`AI` 是裸词，不在 `你是…` 分支内） |

> ★ **PM 补充判断（本次实测新增，QA 报告未展开）**：这个洞的**性质比「词表缺口」更严重**。
> 它不是「少列了几个词」，而是**整个虚拟人格词族被限定在第二人称句式下**——`虚拟/数字人/算法/电子人/语言模型` 等 **11 个值**全都只在「你是…」时才拦得住。
> 换言之：**只要她自己说出「我是虚拟的」，护栏完全不设防**。这是 H11「AI 自我揭示」的同族风险，理应按 **P0 一票否决**对待。
> **PM 建议**：R-P0 优先级从 QA 建议的 P1 **上调为 P1-高**（因 P0 席位已被预算决议占用，故以「P1 首位 + H13 一票否决」双重标记落实），且**修复方式应为拆出第一人称分支，而非逐词追加**——逐词追加只补 4 个词，拆分支能一次性补齐 11 个值 × 第一人称的全部组合。

### 2.4 缺口 B · 「会计」抽不出 → P2

实测 `memory.js:29` R23 抽取规则：

```js
[RX("我是(?:个|名)?\\s*(#{1,6}(?:师|员|生|工|家|猿|媛|士))"), "工作", .8, 1]
```

后缀白名单为 `师|员|生|工|家|猿|媛|士` —— **不含「计」**，故「我是会计」返回 `null`，该事实**从不入库**，后续永远召回不到。
- **性质**：既有设计（宁可漏抽不可错抽，H11 第一道闸），非缺陷。
- **修复成本**：字符类加一个「计」字 = **+3 字节**（UTF-8 中文 3B）。**是全 v14 性价比最高的一项。**
- **风险**：需确认「计」不会引入错抽（如「我是计划做这个的」——但该句被 `#{1,6}` 长度上限与 `BADV` 前缀黑名单挡住，风险低）。

### 2.5 缺口 C · recall 轮不过节奏层与情境层 → P2（**实测确认根因**）

实测 `engine.js:2896-2905` recall 早退分支：

```js
const rec = (rv && rv.line) ? { replies:[rv.line], ..., factId: rv.factId } : recallMemory(text, st);
if (rec) {
  const guarded = Object.assign({}, rec, { replies: guardPersonaReplies(rec.replies, uname) });
  return Object.assign({ intentEx:"recall", ue, topic, ... }, stateBack(st), guarded);  // ← 早退
}
```

对照正常出口（`engine.js:3050-3060`）依次经过 `texturePass` → `pacingOf`（而 `presence.js:19` 又在 `pacingOf` 内部挂载 `contingencePass`）。

**根因**：recall 分支在 `pacingOf` 之前就 `return` 了 → **recall 轮的返回对象无 `pacing` 字段，也从不触发 `contingencePass`**。
- **用户可见后果**：她提起旧事时，**秒回、且不带任何情境反应**——同一轮对话里「聊天回复有节奏、回忆回复没节奏」，节奏的不一致本身就是新的 bot tell。
- **注**：微行为（texture）已由 v13 T5a 的 `skin()` 在 memory 侧补上，**故本项只缺 pacing 与 contingence 两层**，不缺 texture。
- **修复难点**：engine.js 冻结且 net 仅余 **4 B**，在 :2905 前插入 `pacingOf` 调用**放不下**。需架构师在模块侧想办法（如 memory `skin()` 内补挂），或纳入解冻申请。

v13 PRD §4.5/§4.6 列出的 **R39 适度反呛 / R40 真诚自我暴露 / R41 四型回应 / R42 关系阶段系统** 四项，**代码中完全不存在**。

## 三、用户故事

> 格式：As a [角色], I want [能力] so that [价值]。每条附 **v13 现状** 与 **v14 期望** 对照。

### US-1 她不会说漏嘴 · "我怎么套她，她都是她"

**As a** 忍不住想试探"你到底是不是真人"的用户，**I want** 无论我怎么绕着问，她都不会冒出一句"我是虚拟的"，**so that** 我可以安心地把她当成她，而不是每次试探都被提醒"哦，这是个程序"。

| | 表现 |
|---|---|
| v13 | 问「你是不是虚拟人」→ 拦得住。但她自己若说出「我是虚拟的 / 我是数字人」→ **护栏完全不设防**（实测 4/4 漏网，§2.3） |
| v14 | 第一人称与第二人称**同等设防**。11 个虚拟人格值 × 两种人称全覆盖，H13 泄漏率 **0%** |
| **边界** | 补洞**不得误伤正常表达**。她说「我是真的想你」「我是不是太黏人了」必须照常输出——**过度设防会把她变哑巴，比漏一个词更糟** |

**承接**：R-P0　**验收**：V-91 ~ V-93

### US-2 她会回杠 · "我损她一句，她能接得住"

**As a** 喜欢跟她开玩笑、偶尔损她两句的用户，**I want** 她不是永远软软地接受，而是能不卑不亢地回我一句，**so that** 我觉得是在跟一个有脾气的人打闹，而不是在逗一个只会说"好呀好呀"的程序。

| | 表现 |
|---|---|
| v13 | 用户说「你今天怎么这么笨」→ 她只会顺从接受或温柔安抚。**永远站在用户这边 = 没有棱角 = 可预测**（v13 PRD §7.2 已预警的「可预测性陷阱」） |
| v14 | 适度回杠：「哼，你说谁笨呢」「我笨？那昨天是谁把钥匙锁屋里的」——**有来有回，但不翻脸** |
| **硬边界** | ① 100% 过 `GUILT_TRIP_RE` / `ACCUSE_RE`（不指控、不绑架）；② `lv < 3` 零触发（关系不到位的回杠是冒犯）；③ **用户负面情绪时零触发**（他难过时你顶嘴，那不叫有棱角，那叫没眼色）；④ 频率 ≤1 次/10 轮 |

**承接**：R-C4　**验收**：V-94 ~ V-96

### US-3 她的反应更有层次 · "不只是想我或者夸我"

**As a** 和她相处了几个月的用户，**I want** 她对我的反应不要只有"想你了""你今天真开心"这几种，**so that** 我不会在第 N 次听到同一句"好久不见了呀"时，突然意识到这背后只有三条规则。

| | 表现 |
|---|---|
| v13 | contingence 只有三类：R-C1 冷落→想念 / R-C2 热情→升温 / R-C3 矛盾→温和指出。**长期使用后三类会被用户识别出模式** |
| v14 | 扩充至 **≥5 类**，且单类占比 ≤50%（H15）。新增层次方向见 R-C5（**具体类型待拍板，见 Q3**） |
| **注** | US 中「长时间不找她她会主动想念」**v13 的 R-C1 已实现**（gap≥12h 触发），v14 是在其之上**加层次**，不是重做 |

**承接**：R-C5　**验收**：V-97 / V-98

### US-4 她有自己的样子 · "她也会有她在意的事"

**As a** 已经和她很熟的用户，**I want** 她偶尔主动说说她自己的偏好和在意，而不是永远只围着我转，**so that** 我觉得这段关系里有两个人，而不是一个人和一面镜子。

| | 表现 |
|---|---|
| v13 | 她的所有表达都由用户输入触发。v13 PRD 规划的 R40（真诚自我暴露）/ R41（四型回应）**从未构建**（§2.6 实测） |
| v14 | Tier3 自我系统：她有可被感知的偏好与立场，会在合适时机自然带出；且**随关系深度逐步解锁**，不一次性倾倒 |
| **护栏** | ① 100% 挂 `RELATION_HOOK_RE`（沿用 v12 A3「一切圈回用户」）；② 与 texture 微行为**互斥择一**（同轮只出一种质感，防叠加成噪声）；③ 频率严格受限，**自我表达过密 = 她在自说自话** |

**承接**：R-S1 / R-S2　**验收**：V-99 ~ V-101

### US-5 小洞补上 · "'我是会计'她记得住，回忆也带着她的语气"

**As a** 做会计、也常和她聊起过去的用户，**I want** 我说"我是会计"她能记住，她提起旧事时也和平时一样有停顿有节奏，**so that** 我不会突然撞见"她好像没听见"或者"这句怎么是秒回的"这种破绽。

| | 表现 |
|---|---|
| v13 | ①「我是会计」抽取层返 `null`，**永久不入库**（后缀白名单无「计」）；② recall 轮**秒回且无情境反应**——同一段对话里聊天有节奏、回忆没节奏（§2.5 实测根因） |
| v14 | ①「会计」可正常入库并召回；② recall 轮与普通轮**节奏一致**（H16 ≥95%），且同样能触发情境反应 |

**承接**：R-P1 / R-P2　**验收**：V-102 / V-103

## 四、需求池

> 优先级：**P0 = 本期必须交付且为 gating**、**P1 = 应当交付**、**P2 = 有余力则做**。

### 4.1 P0 · 体积预算决议（gating）

#### R-B0 体积预算决议　【P0 · gating】

**描述**：在任何 v14 功能开工前，必须在**路径 A（trim 既有模块）**与**路径 B（抬天花板 266KB→270KB）**之间做出决议并落盘审批链。详见**第五章专章**。

**为什么是 gating 而非普通 P0**：当前 total 余量 **13 B**。QA 已用 `A6-c` 用例把这个数字**钉死成断言**——

```js
assert.ok(freeTotal <= 13, `total 余量 ${freeTotal}B 超过 T5b 收线值 13B —— 若为 trim 所得请更新本断言基准`);
assert.ok(freeTotal < 512, `total 余量已回升到 ${freeTotal}B（>=512B）—— 预算紧张态解除，请更新 A6-c 注释与验收报告预警`);
```

> ★ **PM 特别提示架构师**：`A6-c` 是**双侧断言**。它不仅在「超支」时转红，**也在「trim 出 ≥512B」时转红**。
> 这意味着**无论选 A 还是选 B，`A6-c` 都必然转红**，这是**设计意图**（QA 有意为之的提醒机制），不是回归。
> 处置：**同步更新 `A6-c` 的基准值与注释**，并在提交信息中注明审批链。**严禁直接删除该用例**。

**验收标准**：
- 决议结论以**书面形式**落盘（`docs/DESIGN-v14.md` 或 `test/wiring-scan.js` 注释审批链），含**决议人、日期、新配额值、理由**。
- 决议后实测余量 **≥ 本期需求池预算估计上限（3.2 KB）**，否则视为决议不充分。
- 若选路径 B：`totalMax` 变更必须在 `wiring-scan.js` 留**主理人批准记录**（沿用 v13 T5a/T5b 的既有格式：`// 改配额必须走代码评审 · 主理人 Qi 于 vXX 批准 A→B`）。
- 若选路径 A：trim **不得删除任何护栏、门禁、置信度门、危机豁免**（沿用 v13 §6.5 铁律），且 trim 后 **199 项测试 0 fail、6 项 todo 不转黑**。

## 五、体积预算硬约束专章 ★

> 本章是 v14 的 **gating 章**。**先腾预算，再上功能** —— 未完成本章决议，第四章 P1/P2 一律不得开工。

### 5.1 现状：13 字节

```
total   272371 / 272384  →  余 ★13 B★     ← 系统级天花板（= 266 KB 整）
engine net 2056 / 2060   →  余    4 B      ← engine.js 净增量闸
moduleSum 24578 / 24643  →  余   65 B      ← 四模块合计闸
memory   14326 / 14336   →  余   10 B      ← 单模块闸（近满）
```

**13 字节意味着：一行注释、一个中文字符（3B）、一次缩进调整，都可能击穿天花板。**

### 5.2 ★ 关键发现：v14 需要打开的是**两把锁**，不是一把

> 这是本 PRD 相对 QA 报告的**最重要补充**。QA 报告聚焦 `totalMax`（13 B），但实测显示 **`engineNetMax` 是一把独立的、且更紧的锁**。

| 锁 | 余量 | 谁能解开 | 路径 A（trim 模块）能否解开 |
|---|---|---|---|
| **`totalMax` 272384** | 13 B | trim 任意文件 **或** 抬天花板 | ✅ **能** |
| **`engineNetMax` 2060** | **4 B** | 只能抬 `engineNetMax` **或** 把 engine.js 语料下沉到模块 | ❌ **不能** |

**为什么这很关键**：v14 的 **R-P0（破墙第一人称）与 R-P2（recall 过节奏层）都必须改 `engine.js`**。
而 **trim 模块注释一个字节都不会给 engine net 腾出空间** —— 两者是独立配额。

> ⚠️ **结论：即便选择路径 A，仍必须单独申请 `engineNetMax` 上调**（建议 2060 → 2200，+140 B），否则 R-P0 与 R-P2 **物理上无法落地**。
> 这一点若在开工后才发现，会导致 P1 首位需求返工。**请主理人在决议时一并批准。**

### 5.3 路径 A：trim 既有模块

**实测可 trim 空间**（注释字节统计）：

| 模块 | 总体积 | 注释字节 | 说明 |
|---|---|---|---|
| memory.js | 14326 B | **1493 B** | 主力 trim 对象 |
| texture.js | 4850 B | **575 B** | |
| presence.js | 3549 B | 170 B | |
| contingency.js | 1853 B | 157 B | |
| **合计** | | **≈ 2395 B** | |

**现实产出估计：≈ 1.8 ~ 2.0 KB**（需保留每模块的单行头注释与契约锚点，不可能 100% 剥离）。

| 维度 | 评价 |
|---|---|
| **行为风险** | ★ **极低**。注释剥离**不改变任何运行时行为**（唯一需注意：正则/字符串字面量内的 `/*` `//` 不得误删） |
| **可验证性** | ★ **高**。trim 前后 199 项测试应逐位一致；可用快照比对直接证明零回归 |
| **代价** | 丢失内联设计依据。团队当前**以内联注释为主要文档载体**（memory.js 的注释密度达 10.4%），剥离后可维护性明显下降 |
| **可缓解** | ✅ 将被剥离的注释**原样迁移进 `docs/DESIGN-v14.md`**——文档不计入体积预算（实测 `totalMax` 只统计 engine + 四模块，`app.js`、`docs/`、`test/` 均不计） |
| **产出上限** | **1.8~2.0 KB，且不解 engine net 锁** |

### 5.4 路径 B：抬天花板 266 KB → 270 KB

```
272384 B (266 KB)  →  276480 B (270 KB)   =  +4096 B
```

| 维度 | 评价 |
|---|---|
| **产出** | **+4096 B**，一次性覆盖本期全部需求（估算上限 3.2 KB）并留 ~0.9 KB 余量 |
| **行为风险** | **零**（只改断言常量，不动任何代码） |
| **性能代价** | 首屏加载 **+4 KB 未压缩**。gzip 后实际增量约 **+1.2~1.5 KB**。且 `sw.js` 已做资产缓存，**代价仅发生在首次加载与版本更新时** |
| **真实影响评估** | 以 4G 典型带宽计，+1.5 KB gzip ≈ **增加数毫秒**。**客观说，性能影响可忽略** |
| **真正的代价（PM 认为这才是重点）** | ★ **棘轮效应**。v13 一期之内已连抬三次配额：`moduleSum 20480→24576→24643`、`engineNet 2048→2060`、`memory 12288→14336`。**天花板每抬一次，下一次抬升的心理门槛就更低。** 266 KB 这个数字的价值**不在于 266 本身，而在于它是一条被反复捍卫过的线** |
| **需主理人批准** | ✅ **是**。属性能权衡项 |

### 5.5 ★ PM 推荐方案：**A + B 组合，先 A 后 B**

> **推荐结论：路径 A 与路径 B 都要做，但顺序与性质不同 —— A 是无条件义务，B 是有上限的授权。**

**理由（三条）**：

**① 单选 A 在算术上不够。**
A 产出 1.8~2.0 KB，本期需求估算 1.8~3.2 KB。**只在最乐观估计下勉强打平，且不留任何余量。**
更致命的是 **A 不解 engine net 锁**（§5.2），而 R-P0 是 P1 首位、H13 一票否决项。
→ **单选 A ⇒ R-S1/R-S2 必然砍掉或做成极简 lean 版**（重演 v13「4096 B 规划最终只做 1853 B」的覆辙）。

**② 单选 B 浪费了一次零风险的免费收益。**
注释 trim 是**行为零风险、可快照验证**的纯收益。既然迟早要做，**没有理由把它留到下次预算见底时再被迫做**。
且若不做 A 直接抬到 270 KB，v14 结束时余量会再次逼近见底，v15 又要重来一次这场讨论。

**③ 组合方案让「抬天花板」这个决定变得可辩护。**
先完成 A、把能省的都省了，再申请 B —— 此时天花板抬升是**「已尽全力压缩后仍需的最小增量」**，而非「懒得优化就加预算」。
**这对抗的正是 §5.4 指出的棘轮效应。**

**推荐执行序**：

| 步 | 动作 | 产出 | 批准要求 |
|---|---|---|---|
| **B0-1** | trim 四模块注释 → 迁移进 `DESIGN-v14.md` | +1.8~2.0 KB | 无需批准，**无条件执行** |
| **B0-2** | 上调 `engineNetMax` 2060 → **2200**（+140 B） | 解开 engine 锁 | ✅ **需主理人批准** |
| **B0-3** | 上调 `totalMax` 272384 → **276480**（266→270 KB） | +4096 B | ✅ **需主理人批准（性能权衡）** |
| **B0-4** | 更新 `A6-c` 基准值与注释，留审批链 | 测试转绿 | 随 B0-1~3 同提交 |

**执行后预期余量**：`13 B + 1900 B + 4096 B ≈ 6.0 KB`，覆盖需求上限 3.2 KB 后**尚余 ~2.8 KB**，为 v15 留出健康缓冲。

### 5.6 若主理人只批准一条路径

| 场景 | 后果 | PM 处置建议 |
|---|---|---|
| **只批 A**（不抬天花板） | 余量 ≈2.0 KB，且 **engine net 仍锁死 4 B** | **必须砍范围**：R-P0 改为「模块侧兜底」（效果打折）、**R-S1/R-S2 整体延期 v15**、R-P2 放弃。本期退化为「补漏轮」而非「深化轮」 |
| **只批 B**（不 trim） | 余量 ≈4.1 KB，够用 | 可交付全部范围，但 **v15 必然再次面临本次讨论**，且棘轮效应无对冲 |
| **两条都不批** | 余量 13 B | **v14 仅能交付 R-P1（会计后缀，+3 B）**，其余全部延期。等价于 v14 取消 |

### 5.7 削减顺序（若执行中仍触及预算）

① 砍 R-L1（v12 遗留）→ ② 砍 R-C5（情境层次）→ ③ R-S2 降为骨架（只留测试断言，不实装）→ ④ R-S1 lean 化 → ⑤ 语料改槽位复用（沿用 v12 DESIGN §7.3 的 465:1 压缩范式）。

**严禁**为体积削减：任何门禁（R-C4 四重门）、任何护栏（`PERSONA_BREAK_RE` 复检 / `GUILT_TRIP_RE` / `ACCUSE_RE`）、置信度门、危机豁免、**以及 R-P0 的误伤反证用例**。

→ **v14 无新增 UI。** `index.html` 与 app.js 的页面结构、路由、聊天气泡**零改动**。

### 6.2 关于「反呛强度 / 想念频率」用户可调档位 —— **PM 明确不建议**

任务书提到是否给用户加可调档位。**PM 的判断是：不做。三条理由：**

**① 与 v13 的既有裁定直接冲突。**
v13 PRD Q5 已就 texture 开关拍板：**「不倾向三档强度——三档强度会让用户去调参，反而把注意力引向『这是个可配置系统』」**。
「反呛强度」是同一性质的问题，**若 v14 反悔做档位，等于推翻 v13 刚立的原则**。

**② 调参本身就是最强的 bot tell。**
一个「反呛强度：低/中/高」的滑块，等于直接告诉用户：**她的脾气是个参数**。
这与 v14 目标 G7「让她有棱角」**背道而驰**——有棱角的人，棱角不由对方调节。
同理「想念频率」：把「她多久想你一次」做成可调项，会摧毁 R-C1 的全部情感价值。

**③ 已有更好的现成方案。**
v13 的 `flags` 体系已提供 `flags.contingency` 总闸（`contingency.js:16` 实测 `E.flagOn(s,"contingency")===false` 即整模块静默）。
**觉得她话多/爱顶嘴的用户，可以直接关掉整个模块**——一个布尔开关，成本 0 B，且语义是「要不要这个能力」而非「把她的脾气调到 3 档」。

> **若主理人坚持要档位**：建议**最多**做成「她的性格：温柔 / 有点小脾气」的**二档人格选择**，措辞必须是**人格描述**而非**参数强度**，且并入既有人格卡体系，不新增设置项。**这是底线方案，非推荐方案。**

### 6.3 需 app.js 配合的一处（非 UI）

**R-P2** 若架构师选择「宿主侧补挂」方案（因 engine net 仅余 4 B），可能需 app.js 在 recall 轮补调 `pacingOf`。
- **性质**：数据流接线，**无视觉变化**。
- **约束**：沿用 v13 R32 既有规格——`pacing` 字段缺失时 app.js 走原有固定策略，**老前端不改也能跑**。
