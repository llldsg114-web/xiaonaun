# PRD-v17 体积预算重谈与三流工作流收敛

## 1. 产品目标

**v17 一句话目标**：在 H13 零泄漏守恒与「体积四锁」不可破的硬约束下，将 engineNet 预算重谈从隐含约束升级为显式章节，承接 v16 收敛后的三流工作流（R2-A5b / Q-P2-D11 / R-S2），并同步治理护栏归一化前置（含 19 个消费点折叠不一致）。

**与 v16 承接**：
- v16 已在 T2-d 关闭 A2-i 与 R2-B4；R-L1 父项（v14 定义的 v12 遗留四项）因此收敛为仅余 R2-A5b + Q-P2-D11。
- v17 真实工作流确认为 **3 条**（原 briefing 重复计数 R-L1 为独立项，已纠正），预算门槛是真实算术而非流程问题。
- v16 遗留教训：V33 必须随 engineNetMax 同步更新，否则 T0 首日两红断言。

本 PRD 所有体积数字以 Buffer.byteLength 实测为准。

- P0-2 H13 零泄漏守恒：破墙密闭性 0% 一票否决；验收六维 1,034,880 + 异构网格，leak 必须=0。
- P0-3 V33 同步更新纪律：engineNetMax 任何变更必须同步 V33，否则 T0 首日两红断言。
- P0-4 体积四锁不得破：moduleSumMax / engineMax / engineNetMax / totalMax 恒等式维持自洽，松弛≥0。

### P1（应该）

- P1-2 Q-P2-D11：高水位≈119B / 日期集≈90B，按高水位 119B 计入。

## 4. 预算重谈（核心章节）

**实测基线**：模块侧闲置总额 = 2540B（memory 783 + presence 539 + texture 763 + contingency 455），与 moduleSumMax 28343 − moduleSum 25803 = 2540B 自洽。engineNet 仅余 50B，而 engine 侧合计算造价 ≈320–350B → 门槛是真实算术约束，非流程。

**选项 A 模块→engine 让渡**：从 moduleSumMax 让渡 400B 给 engineNet。
- 自洽示例：engineNetMax 2400→2800，engineMax 248137→248537，moduleSumMax 28343→27943，contingency 抬至 5418，四锁恒等式全成立、松弛 0。
- 代价：与 R-S2（≈900B）争夺同一 contingency 池，非免费。

**选项 B 冻结 R-S2 二期**：推迟/砍掉 Tier3 二期，contingency 仅须承接 455B 闲置，engineNet 余 50B 不再恶化。代价：放弃 Tier3 二期能力，与产品路线冲突。

**选项 C 抬总上限（四锁重设）**：直接抬高 ceiling 治本。代价：改动面大，必须 V33 随 engineNetMax 同步更新，需全量回归。

**触发条件**：
- T1：engineNet 余量(50B) < 工作流造价(320–350B) → 已满足，必须谈。
- T2：R-S2(≈900B) 与 A 让渡后 contingency(5418B) 净余不足 → 触发 B/C 降级。

**推荐路径**：首选 A（Δ=+400 已证四锁自洽、松弛 0），**强制 V33 随 engineNetMax 同步更新**（漏改则 T0 首日两红断言）；R-S2 二期由抬升后 contingency 余量承接，若净余 < 900B 则降级到 C（抬 ceiling）而非 B（保功能优先于砍功能）。
